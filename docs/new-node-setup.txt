INCHELLA VPN — КАК ПОДКЛЮЧИТЬ НОВУЮ НОДУ С REALITY SELF-STEAL
Актуально: 2 ноября 2026 года

Эта памятка рассчитана на отдельную новую VPS с Ubuntu 24.04 или 26.04 x86_64,
готовую панель Remnawave и поддомен в Cloudflare. Она описывает схему:
клиент -> публичный inbound Xray -> локальный nginx 127.0.0.1:9443.
Команды выполняются на новой VPS под root, если не сказано иначе.
Перед массовым применением новой версии скрипта проверь её на тестовой VPS.

Перед началом запиши для себя (не публикуй секреты):
- публичный IPv4 новой VPS и выбранный поддомен, например xx01.inchella.cfd;
- актуальный IP панели Remnawave (на 31.10.2026: 83.219.248.110);
- NODE_PORT, который выдаст панель (часто 2222), и SSH-порт;
- публичные VPN-порты: обязательно один inbound на 443 для HTTPS-редиректа,
  а при необходимости второй, например XHTTP/8443;
- какие Config Profile, Hosts и Internal Squad относятся именно к этой ноде.
Примеры IP, домена и портов ниже замени своими. Не копируй SECRET_KEY,
privateKey, токены панели и пароли в чаты, скриншоты или публичный Git.

1. ПРОВЕРЬ VPS И ДОСТУП

Сохрани рабочую SSH-сессию. Проверь ОС, архитектуру, контейнеры и порты:

  cat /etc/os-release
  uname -m
  docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
  ss -lntp

Для первого запуска установщика нужны Ubuntu 24.04 или 26.04 x86_64,
свободные TCP/80 и TCP/9443, отсутствие ранее установленного nginx и
сертификата Let's Encrypt для выбранного домена. Если nginx уже установлен,
не запускай установщик поверх него: сначала разберись с конфигурацией.

2. СОЗДАЙ REMNANODE И СВЯЖИ ЕЁ С ПАНЕЛЬЮ

Установи Docker, если его ещё нет. В Remnawave открой Nodes -> Management,
создай ноду с её настоящим IP и выбранным NODE_PORT. Скопируй выданный панелью
docker-compose.yml на VPS и запусти Remnanode по официальной инструкции:
https://docs.rw/install/remnawave-node/

В Compose у Remnanode должен быть network_mode: host. Иначе Xray внутри
контейнера не увидит локальный nginx на 127.0.0.1:9443. NODE_PORT в Compose
и карточке ноды должен совпадать. Это управляющий порт панели, не порт VPN.
Дождись состояния Online. На время создания можно выбрать отдельный профиль,
не занимающий TCP/80 и TCP/9443; профиль Self-Steal назначишь позже.

3. СОЗДАЙ DNS-ЗАПИСЬ

В Cloudflare создай A-запись выбранного поддомена на IPv4 именно новой VPS.
Proxy status: DNS only. TTL: Auto. Для этого имени не создавай AAAA-запись,
если IPv6 для клиентов не настраиваешь. Не перенаправляй домены панели или
других нод. Если заменяешь действующую ноду, учти, что старые подписки
с тем же доменом сразу начнут вести на новый IP.

Дождись обновления DNS. Проверь A-запись:

  resolvectl query xx01.inchella.cfd

До выпуска сертификата TCP/80 должен быть доступен из интернета — проверь
также правила сетевого экрана в кабинете VPS-провайдера.

4. СКАЧАЙ И ПРОВЕРЬ SELF-STEAL

На новой VPS:

  apt-get update
  apt-get install -y --no-install-recommends git curl ca-certificates openssl iproute2 python3-configobj
  git clone https://github.com/Inch1337/Remnawave-Selfsteal-Nginx.git /opt/remnawave-selfsteal
  cd /opt/remnawave-selfsteal
  git log -1 --oneline
  bash install.sh --check

Когда проверка спросит домен, введи поддомен из шага 3. Продолжай только
после "Initial checks passed". Режим --check не меняет систему. Если он
сообщает об ошибке DNS, сети, порта или существующего nginx, сначала исправь
именно эту причину. Не меняй REALITY target и SNI до готовности nginx.

5. УСТАНОВИ И ПРОВЕРЬ ЛОКАЛЬНЫЙ САЙТ

Из /opt/remnawave-selfsteal:

  set -o pipefail
  bash install.sh --install 2>&1 | tee install.log
  bash check.sh

Для Let's Encrypt введи тот же домен и свой контактный email. Ожидай
"Installation complete" и затем "SELF-STEAL READY" при всех [OK].
Установщик выпускает сертификат, настраивает nginx на 127.0.0.1:9443,
проверяет пробное продление и включает таймер Certbot. Обычные запросы
на HTTP/80 перенаправляются на HTTPS; путь /.well-known/acme-challenge/
остаётся на HTTP для продления сертификата. TCP/9443 наружу не открывай.

6. НАСТРОЙ ОТДЕЛЬНЫЙ CONFIG PROFILE В REMNAWAVE

Если профиль используется другими нодами, сделай отдельную копию для новой:
изменение общего профиля затронет их подключения. В каждом нужном inbound
REALITY укажи:

  realitySettings.target      = "127.0.0.1:9443"
  realitySettings.serverNames = ["xx01.inchella.cfd"]
  realitySettings.xver        = 0

Имя в serverNames должно совпадать с доменом сертификата nginx. Не оставляй
сторонний SNI, например ya.ru, если локальный сайт выдаёт сертификат только
для xx01.inchella.cfd. Для совершенно нового профиля сгенерируй ключевую пару
REALITY и Short ID (имя контейнера и бинарника проверь на своей ноде):

  docker exec remnanode xray x25519
  openssl rand -hex 8

PrivateKey из вывода первой команды используй только в серверном профиле,
публичный ключ — в клиентских параметрах, Short ID — в обоих. Если профиль
уже работает, не меняй существующие ключи и Short ID без причины. Сохрани
настройки транспорта, маршрутизации и DNS. Для XHTTP сохрани его
xhttpSettings, в том числе path и mode.

После установки этого скрипта обычный HTTP перенаправляет на HTTPS/443.
Поэтому на новой ноде должен работать хотя бы один REALITY inbound на 443,
например TCP/REALITY или XHTTP/REALITY. Если дополнительно нужен второй
вариант, можно использовать XHTTP/8443. Два inbound нельзя просто назначить
одному и тому же порту одновременно.

В Nodes -> Management назначь этот Config Profile новой ноде и включи
нужные inbound. Проверь, что Xray запустился и нода осталась Online.

7. СОЗДАЙ HOSTS И ДОСТУП ПОЛЬЗОВАТЕЛЯМ

В Remnawave один Host выбирает один inbound. Для каждого варианта подключения
создай отдельный Host:

  Address = xx01.inchella.cfd
  Port    = публичный порт выбранного inbound (например 443 или 8443)
  SNI     = xx01.inchella.cfd

Включи Host visibility. В Internal Squad включи те же inbound, которые
должны видеть пользователи. Убедись, что пользователь входит в нужную
группу, его подписка содержит новый Host, а клиент обновил подписку.
Адрес 127.0.0.1 и порт 9443 в Host не указывай: они только для связи Xray
с локальным nginx.

8. ВКЛЮЧИ UFW, НЕ ТЕРЯЯ SSH И СВЯЗЬ С ПАНЕЛЬЮ

Если UFW уже активен, добавь недостающие разрешения до установки сертификата.
Если он выключен, сначала подготовь все правила. Ниже пример для SSH/22,
NODE_PORT/2222, TCP/443 и XHTTP/8443; замени порты и IP панели, если они иные:

  ufw default deny incoming
  ufw default allow outgoing
  ufw allow 22/tcp
  ufw allow 80/tcp
  ufw allow 443/tcp
  ufw allow 8443/tcp
  ufw allow from 83.219.248.110 to any port 2222 proto tcp
  ufw show added

Сверь правила, затем:

  ufw enable
  ufw status verbose

NODE_PORT должен быть доступен только с IP панели. SSH разрешай до включения
UFW; не закрывай старую SSH-сессию, пока новая не открылась. Убедись, что
Remnawave после этого показывает ноду Online. Если используешь только один
VPN-порт на 443, не открывай 8443. При наличии публичного IPv6 проверь и правила
UFW для IPv6. Правила в кабинете провайдера должны согласовываться с UFW.

9. ПРОВЕРЬ СЕРВИС СНАРУЖИ И ИЗ КЛИЕНТА

С другой VPS или из сети без VPN проверь домен. Подставь свой домен и IP:

  curl -I http://xx01.inchella.cfd/
  curl -Iv --resolve xx01.inchella.cfd:443:IP_НОДЫ https://xx01.inchella.cfd/

На HTTP/80 ожидается 301 и Location: https://xx01.inchella.cfd/.
На HTTPS/443 ожидаются действительный сертификат домена и ответ сайта.
Для дополнительного XHTTP/8443 используй тот же curl с портом 8443
в --resolve и URL.

На самой ноде:

  cd /opt/remnawave-selfsteal
  bash check.sh
  certbot renew --dry-run --run-deploy-hooks --cert-name xx01.inchella.cfd

Ожидай "SELF-STEAL READY" и успешное пробное продление. Проверь, что
подключение через ноду работает на телефоне и в TUN, а сервис доступен
из нескольких реальных сетей пользователей. Отчёт сканера — дополнительная
подсказка; один результат не доказывает механизм блокировки ТСПУ.

10. ПОСЛЕ ЗАПУСКА И ПРИ ОБНОВЛЕНИИ

Следи за сроком сертификата, свободным местом, состоянием ноды в панели
и доступностью из разных сетей. Перед изменением действующей ноды сохрани
Config Profile и параметры Hosts. Обновление скрипта выполняй так:

  cd /opt/remnawave-selfsteal
  git pull --ff-only
  set -o pipefail
  bash install.sh --install 2>&1 | tee install-update.log
  bash check.sh

Если установка или проверка завершилась ошибкой, остановись и изучи лог;
не удаляй наугад nginx, сертификат, контейнер или каталог состояния.
Не публикуй логи, Compose и скриншоты с SECRET_KEY, privateKey и токенами.

Полная инструкция и детали ошибок находятся в README.md этого проекта.
